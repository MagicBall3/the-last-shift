# Архитектура

## Слои

```
React (ui/, App.tsx, game/GameCanvas.tsx)   — экраны, настройки, HUD, тач-кнопки
        │  создаёт/уничтожает, вызывает pause()/resume()/applySettings()
        ▼
game/GameSession.ts                          — корень композиции (единственное место, где всё собирается)
        │
        ▼
core/Engine.ts  ──update()──►  модули (GameModule), порядок = порядок регистрации
```

React не знает о Three.js. Игра не знает о React; наружу сообщает только через `GameEvents` (core/types.ts).

## Порядок обновления кадра

1. `PlayerController` — опрашивает `InputManager`, двигает `Player`
2. `FirstPersonCamera` — ставит камеру в глаза игрока, покачивание
3. `InteractionSystem` — луч из центра экрана, подсказка, нажатие «действие»
4. `World` — анимация дверей
5. `Flashlight` — фонарь (F)
6. `Lighting` — пул ламп: назначение ближайших источников, мерцание

Новые модули (враг, шаги, фонарь) добавляются в `GameSession` после существующих, если не нужен иной порядок.

## Папки

| Папка | Назначение |
|---|---|
| `core/` | Engine, config, типы, platform (тач, WebGL, полноэкранный режим) |
| `world/` | см. раздел «Мир» ниже |
| `player/` | состояние игрока и физика движения; `PlayerController` связывает с вводом |
| `camera/` | `FirstPersonCamera` |
| `controls/` | `InputSource` → `InputManager` → `InputFrame`; клавиатура/мышь и тач |
| `lighting/` | `Lighting` (пул ламп), `Flashlight`, `LightDef` |
| `audio/` | `AudioManager` — процедурный звук без файлов |
| `interactions/` | `Interactable`, `InteractionSystem` |
| `saves/` | LocalStorage: настройки и прогресс, с валидацией |
| `ui/` | React-компоненты и `strings.ts` (все тексты) |
| `game/` | `GameSession` (композиция), `GameCanvas` (React-обёртка) |

## Принятые решения (не менять без причины)

1. **Чистый Three.js + императивный `GameSession`**, а не react-three-fiber: меньше накладных расходов на слабых телефонах, игра отделена от React.
2. **Three.js в отдельном чанке** (динамический импорт): меню и загрузка открываются, пока движок догружается.
3. **Единый `InputFrame`**: любой источник ввода (клавиатура, мышь, тач, в будущем геймпад) только пишет в него.
4. **Конфигурация в `core/config.ts`**: скорости, свет, туман, пресеты качества. Числа не размазываются по коду.
5. **Каждая сессия создаёт свой canvas** и полностью освобождает GPU-ресурсы в `dispose()` (безопасно для React StrictMode и выхода в меню).
6. **Адаптивное разрешение**: если кадры стабильно медленные, масштаб рендера снижается (до 0.55), обратно не растёт — чтобы не было качелей.
7. **Тени выключены** на этом этапе (дорого для мобильных). Решение по теням принимать вместе с дизайном уровня.
8. **Звук процедурный**: контекст создаётся только по клику «Начать смену».
9. **Сохранения версионируются** (`save.version`) и проходят через `sanitize*`: повреждённые данные не ломают игру.
10. **Тексты интерфейса — в `ui/strings.ts`.**

## Мир (этап 2)

Карта комплекса — **данные**, а не код: `world/layout.ts` (зоны-прямоугольники, двери, запертые двери, спаун). Из неё `Grid` строит клетки 1×1 м, а `shell.ts` автоматически строит пол, потолок и стены на границах «пол ↔ бетон». Поэтому здание единое, а коллизии точные (круг игрока против клеток).

| Файл | Назначение |
|---|---|
| `layout.ts` | планировка: меняется только он, чтобы изменить здание |
| `grid.ts`, `Collision.ts` | сетка клеток и столкновения |
| `shell.ts` | пол/потолок/стены; участки стен (`WallRun`) для деталей |
| `StaticBatch.ts` | склейка геометрии по материалам (десятки вызовов отрисовки вместо сотен) |
| `textures.ts` | процедурные текстуры (canvas) и материалы (Lambert — дешевле PBR) |
| `structures.ts` | рамы и указатели дверей, запертые двери |
| `props.ts` | свет, балки, трубы, обстановка помещений |
| `Door.ts`, `signs.ts`, `context.ts` | двери, атлас вывесок, инструменты построения |

Новое помещение: добавить прямоугольник в `ZONES`, дверь в `DOORS`, обстановку в `props.ts`. Запертые двери (`LOCKED_DOORS`) — заготовки закрытых комнат: за ними пока бетон. Подпись двери: `[помещение с большей стороны, помещение с меньшей]`.

### Решения этапа 2

11. **Пул ламп**: ламп в здании 24, но реальных `PointLight` — 3/4/5 (по качеству), они переходят к ближайшим лампам игрока через плавное затухание. Число источников постоянно, шейдеры не перекомпилируются. Остальные лампы — видимое свечение (Basic-материал).
12. **Тёмные участки — часть дизайна**: в середине главного коридора и сервисных проходах ламп нет или они мёртвы; ориентироваться помогают аварийные красные лампы, светящиеся вывески и фонарь.
13. **Фонарь всегда на сцене** (яркость 0 = выключен), чтобы не менять число источников.
14. **Двери**: коллизия — `Box3` двери в общем списке; открыта = `makeEmpty()`. Закрыть дверь, пока игрок в проёме, нельзя.
15. **Невидимые прокси для осмотра предметов** (`visible = false`, но участвуют в луче): обстановка склеена в статику и сама не кликабельна.
16. **Детерминированная генерация**: зерно в `CONFIG.world.seed`, здание и мусор одинаковы при каждом запуске.

## Мир (этап 3): карта комплекса

Сетка выросла до 48×46 м. Всё по-прежнему данные: `layout.ts` → `Grid` → `shell.ts`. Добавлено 7 типов зон (`office`, `staff`, `server`, `medical`, `isolation`, `tech`, `airlock`): у каждой свой оттенок материала (`shell.ts` → `STYLE`, `textures.ts` → `createMaterials`). Новых текстур нет — оттенки существующих.

```
 север   кабинеты 2,3 ── северная галерея ── медблок ── изолятор (палаты И-1, И-2)
            │                │  │               │
 запад   кладовая ─ сев. коридор─ персонал    лаборатория А     кабинет 1 · архив
            │                       │               │                 │
         вестибюль ═ КОНТРОЛЬ ═ ГЛАВНЫЙ КОРИДОР (38 м) ═══════════════ ШЛЮЗ 1 (гермоворота, будущий выход во двор)
        (лифт, резерв)    охрана · склад · электрощитовая · серверная ─ техзона
            │                       │
 юг      зап. проход ── южный сервисный коридор ── шлюз 2 ── лаборатория Б
                                    ├── испытательная камера (тупик)
                                    └── тупиковая ветка ── вентиляционная (тупик)
```

Маршруты образуют петли: вестибюль → север → галерея → лаборатория → главный коридор; серверная ↔ техзона (техзона заперта со стороны главного коридора).

| Зона | Назначение / отличия |
|---|---|
| Вестибюль (контроль доступа) | будки поста допуска, перемычка с табличкой над входом в коридор; лифт — резерв `ELEVATOR_RESERVE` |
| Кабинеты 1–3, архив | ковровый тон пола, столы, картотека |
| Комната персонала, кладовая | тёплые стены и пол, диван, шкафчики; кладовая — тупик |
| Серверная | холодный синий свет, стойки с индикаторами |
| Техзона, вентиляционная | янтарный свет, силовая колонна, трансформатор, генератор |
| Медблок, изолятор | бледно-зелёная плитка, зелёный крест — ориентир; палаты без света |
| Шлюз 2, лаборатория Б, камера | дезактивационный тамбур; биолаборатория с большим резервуаром — ориентир; камера с креслом — тупик |

### Резервы под будущее
- **Лифт:** `ELEVATOR_RESERVE` (x 0–1, z 18–20) за западной стеной вестибюля; двери лифта уже стоят (`LOCKED_DOORS`, `kind: 'elevator'`). Нужно вырезать зону и убрать запертую дверь.
- **Двор и новые здания:** `COURTYARD_EXIT` — гермоворота «ШЛЮЗ 1» в конце главного коридора. Для расширения на восток увеличить `GRID_W`.
- **Запертые помещения:** `ТЕХЗОНА` (снаружи), `КОМНАТА 5`, `ЧИСТАЯ ЗОНА` — за дверями пока бетон.

### Проверка карты без браузера

`npx tsx scripts/check-walk.ts` — проход круга игрока (r = 0,3 м) через все двери с учётом мебели. Три.js не нужен.
Запускать после любого изменения `layout.ts` или `props.ts`.

## Мир (этап 4): многоуровневый комплекс NADIR

Комплекс — это **семь уровней** в одной сцене. Каждый уровень строится в локальных координатах
(пол 0, потолок `CONFIG.world.height`) и оборачивается в `Group` со смещением по Y.

| Индекс | Уровень | baseY | Сетка |
|---|---|---|---|
| 0 | Наземный этаж + внешняя территория | 0 | 128×96 |
| 1 | Этаж 2 — администрация | +3.2 | 48×46 |
| 2 | Этаж 3 — аналитика | +6.4 | 48×46 |
| 3 | Этаж 4 — руководство и наблюдение | +9.6 | 48×46 |
| 4 | Уровень −1 — лаборатории | −3.2 | 48×46 |
| 5 | Уровень −2 — изоляция и сектор капсулы | −6.4 | 48×46 |
| 6 | Уровень −3 — серверные, архив, энергетика | −9.6 | 48×46 |

| Файл | Назначение |
|---|---|
| `world/levels/Level.ts` | один уровень: сетка + оболочка + обстановка + двери + коллизия |
| `world/levels/buildLevels.ts` | композиция всех уровней (единственное место, где они перечислены) |
| `world/levels/stairs.ts` | координаты лестничных ниш и карта переходов `stairTarget()` |
| `world/levels/LevelTransitions.ts` | модуль переходов: плавный подъём/спуск, флаг «взведено» |
| `world/levels/levelIndex.ts` | выбор активного этажа по высоте игрока |
| `world/levels/MultiLevelCollision.ts` | `CollisionQuery` поверх всех уровней |
| `world/levels/layout-exterior.ts`, `props-exterior.ts` | внешняя территория |
| `world/levels/layouts-upper.ts`, `props-upper.ts` | этажи 2–4 |
| `world/levels/layouts-underground.ts`, `props-underground.ts` | подземные уровни |
| `world/levels/props-stairs.ts` | визуальные марши, перила, указатели, свет лестниц |

### Как работает вертикальное перемещение

1. `LevelTransitions` проверяет, находится ли игрок в одной из двух лестничных ниш
   (`STAIR_UP_NICHE` — вверх, `STAIR_DOWN_NICHE` — вниз); координаты одинаковы на всех уровнях.
2. `stairTarget(index, dir)` возвращает индекс целевого уровня по явной карте
   (0→1→2→3 вверх; 0→4→5→6 вниз), а не простым `±1`: у подземных уровней отрицательных индексов нет.
3. Позиция игрока ведётся по `easeInOut` за 1.8 с; обычное движение отключено флагом `player.transitioning`.
4. Приземление — в центре той же ниши на целевом уровне. Флаг «взведено» снимается только после
   выхода из обеих ниш, поэтому игрок не «зацикливается» на лестнице.
5. `MultiLevelCollision` выбирает уровень по ближайшей высоте (`levelIndexAt`), проверки остаются 2D.

### Производительность многоуровневого мира

- **Видимость**: в сцене видны активный этаж и соседние (`World.applyVisibility`), остальные скрыты.
- **Свет**: каждая лампа помечена индексом этажа (`LightDef.level`); `Lighting` берёт в пул только
  лампы активного этажа, иначе лампы соседних этажей заняли бы все слоты.
- **Склейка**: каждый уровень клеится в собственные меши по материалам (`StaticBatch`), поэтому
  вызовов отрисовки столько же, сколько было у одного этажа × число видимых уровней (обычно 2–3).
- **Дальность камеры** увеличена до 120 м, туман разрежен (0.02) — иначе внешняя территория не видна.

### Внешняя территория (уровень 0)

Сетка 128×96: здание занимает x 0–47, дальше — двор. Ограждение — бетон по краю сетки
(на север/восток/юг добавлены металлические столбы и колючка). Есть главные ворота с
аварийной лампой, КПП со стенами, дорога с разметкой и фонарями, парковка с автомобилями,
подстанция с трансформаторами, вентиляционные сооружения, погрузочная зона, мусор и пятна.
КПП вырезана как помещение внутри стен — земля вокруг разбита на прямоугольники в обход будки.

### Индивидуальность этажей

Каждый этаж имеет свою тему (`FloorTheme`): `admin` (картотека, тёплый свет), `analysis`
(приборы, сбоящие лампы), `command` (стена мониторов, холодный свет). Подземные уровни:
−1 — лаборатории с рабочими островами; −2 — изоляторы с койками и сектор разбитой капсулы №3
(повреждённое оборудование, стекло, следы на полу); −3 — серверные, архив и энергетика.

## Проверки без браузера

```
npx tsx scripts/check-layout.ts   # планировка и связность «здание + территория»
npx tsx scripts/check-walk.ts     # проход игрока через двери с учётом мебели
npx tsx scripts/check-levels.ts   # связность каждого из 7 уровней
npx tsx scripts/check-stairs.ts   # карта лестничных переходов и приземлений
npx tsx scripts/smoke-world.ts    # сборка всего мира (заглушка canvas), ловит ошибки атласа/материалов
```

`check-layout.ts` и `check-walk.ts` проверяют наземный этаж, `check-levels.ts` — все уровни,
`smoke-world.ts` — фактическое построение сцены.
